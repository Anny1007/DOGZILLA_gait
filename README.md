# DOGZILLA S1 步態穩定測試環境

目標：**解決 DOGZILLA S1 加裝光達後走路很晃的問題**，之後打算用強化學習改善步態。
這個資料夾先建好「量得出晃多少」的測試環境：固定的場景、測試項目與指標。

> **狀態（2026-10-06）**：檔案已完成，模型檔已驗證可以正確展開，但整套測試**還沒在 Gazebo 實際跑過**，數字與工具可能還需要修正。
有了可靠的基準，才能比較加裝光達前後的差別，以及強化學習改善了多少。

和主專案 [`../DOGZILLA/sim_env`](../DOGZILLA/sim_env) 的分工：

| | 主專案 `DOGZILLA/sim_env` | 本資料夾 `DOGZILLA_gait` |
|---|---|---|
| 處理的問題 | 往哪裡走（SLAM、Nav2、RL 避障） | 怎麼走（步態穩定） |
| 啟動的內容 | Gazebo + CHAMP + SLAM + Nav2 + RL | 只有 Gazebo + CHAMP 步態 |
| 測試輸入 | 目標點 | 直接送 `/cmd_vel`、推力 |

## 需求

先在主專案建好映像與 CHAMP（只要做一次，見 `../DOGZILLA/sim_env/SETUP.md`）：

```bash
cd ../DOGZILLA/sim_env && ./run.sh build && ./run.sh colcon
```

本資料夾不需要另外建置。**兩邊的模擬不能同時跑**（都用主機網路），`run.sh` 會檢查。

## 使用方式

```bash
./run.sh sim flat                                   # 空地, 官方模型, 有 Gazebo 畫面
./run.sh sim slope                                  # 10° 斜坡
./run.sh sim flat lidar_mass:=0.17 lidar_z:=0.10    # 背上加 170 g 光達負載
./run.sh stop

./run.sh suite baseline flat                        # 整套平地測試 (無頭), 結果存 results/baseline/
./run.sh suite lidar170 flat lidar_mass:=0.17 lidar_z:=0.10
./run.sh suite slope10 slope
```

整套平地測試約 6～8 分鐘。每個測試都會重新啟動模擬，前一個測試翻倒不會影響下一個。

## 場景（`worlds/`）

| 檔案 | 內容 |
|---|---|
| `flat.world` | 空地 |
| `slope.world` | 前方 1 m 平地 → 10° 上坡（長 1.5 m，高 0.26 m）→ 1.5 m 坡頂平台，寬 1.2 m |
| `slope_5.world` | 同上，5° |

由 `worlds/make_worlds.py` 產生，例如 `python3 worlds/make_worlds.py 7 15` 另外產生 7°、15° 的斜坡。
物理設定（步長 1 ms、地面摩擦 mu 100 / mu2 50）與主專案相同。

## 光達負載（`description/dogzilla_s1_payload.urdf.xacro`）

官方模型的光達只有 **14 g**，整隻狗 0.626 kg。實際加裝的光達通常重幾十到兩百公克，
裝在背上會讓重心變高、偏移，這是實機變晃的可能原因，但**原本的模擬重現不了**。
這個檔案引用主專案的官方模型（不複製），在 `base_link` 上加一個重量和位置可調的方塊：

| 參數 | 預設 | 說明 |
|---|---|---|
| `lidar_mass` | `0.0` | 負載質量（kg），0 就是原本的官方模型 |
| `lidar_x` | `-0.017` | 前後位置（m，相對 `base_link`，與官方光達相同） |
| `lidar_z` | `0.09` | 負載中心高度（m，相對 `base_link`） |
| `lidar_size` | `0.07` | 方塊邊長（m） |

> **待確認**：實際用的光達型號、重量（含支架）與安裝高度。上面的 170 g、0.10 m 只是範例（RPLIDAR A1 等級）。

## 測試項目與指標（`tools/`）

| 測試 | 工具 | 內容 | 指標 |
|---|---|---|---|
| 直走、原地轉、邊走邊轉 | `gait_eval.py`（主專案原樣複製） | 靜止 / 前進 0.2 / 原地轉 0.8 / 前進 0.15 + 轉 0.5，各 6 秒 | 實際速度、晃動 RMS 與最大值、高度起伏、靜止漂移 |
| 翻倒邊界 | `combo_test.py`（主專案原樣複製） | 前進 + 轉向的組合各 8 秒，遇到翻倒就停 | 每組最大 roll / pitch、是否翻倒 |
| 被推一下 | `push_test.py` | 站著側推、站著前推、前進中側推；推 0.1 秒，推力 1→8 N 逐步加大 | 最大傾斜、恢復時間、側向位移、**不會翻倒的最大推力** |
| 斜坡 | `slope_test.py` | 以 0.15 m/s 直走上坡 | 各段速度、晃動 RMS（扣掉坡度）、是否到坡頂 / 翻倒 |

`combo_test.py` 在整套測試裡用的組合是 `0.1,0.4 0.15,0.5 0.2,0.0 0.2,0.2 0.2,0.5 0.2,1.0 0.2,-1.0`
（S1 步態最高 0.2 m/s，原本預設的 0.25～0.3 m/s 會被步態控制器截掉）。
所有量測都用 Gazebo 真值（`/demo/odom/ground_truth`）。

參考數字（主專案 `tools/speed_response.py` 實測，官方模型、無負載）：
指令 0.1 → 實際 0.038 m/s，0.15 → 0.08，0.2 → 0.12～0.13；**0.2 m/s 加轉向 0.2 rad/s 曾經翻倒**。

## 下一步：用強化學習減少晃動（尚未實作）

1. **先量基準**：無負載 vs 有負載（實際光達的重量與高度），確認模擬裡負載真的會讓晃動、推力邊界變差。
2. **選擇強化學習要控制哪一層**，兩種做法：
   - **調整 CHAMP 步態參數或修正量**：RL 輸出步高、站高、身體姿態的修正，CHAMP 照常產生步態。改動小，比較容易移植到實機的原廠韌體。
   - **直接控制 12 個關節**：像學長的 Duo_point（Isaac Lab + Go2），可能做得最好，但要大量平行訓練（Gazebo 做不到），而且實機要能直接下關節指令。
3. 用這裡的 `suite` 比較強化學習前後的數字。
